# PZ_Optimization 한국어 패치

> **`5c72380` 원본 설치 및 한국어 UI 표시 확인 - 장시간/멀티플레이 검증 전**
> 원본 호환 버전: `win-b0bbce05d5-5c72380` · Project Zomboid Build `42.20.4` (`b0bbce05d5`)
> 원제작자: [xD3I/PZ_Optimization](https://github.com/xD3I/PZ_Optimization)

PZ_Optimization의 게임 내 설정 화면을 한국어로 표시하기 위한 별도 패치입니다. 설정 이름과 설명, 그룹 제목, 선택값 안내, 성능 비교 패널 및 Lua 기반 메뉴 문구를 번역합니다. **원본 최적화 기능을 추가·수정하거나 성능을 보장하는 패치가 아닙니다.** 원본 모드를 먼저 설치해야 합니다.

이 저장소는 한국어 번역을 원본과 분리해 관리합니다. 원제작자의 새 릴리스가 나올 때마다 전체 소스와 변경 목록을 비교하고, 그 릴리스에 맞는 패치만 배포합니다. 원본 업데이트 직후 구버전 한국어 패치를 그대로 덮어쓰지 마세요.

기존 `be1f28a` 기반 v4에 이어, `5c72380 + RC2` 환경에서도 한국어 설정 화면 표시를 직접 확인했습니다. 다만 한 차례의 화면 확인과 ESC 테스트만으로 모든 설정, 장시간 플레이, 멀티플레이 호환성이 보장되지는 않으므로 RC로 유지합니다.

### 번역 대상이 아닌 항목

- 비교용 GIF·스크린샷 **그림 자체에 삽입된 영어**
- Java가 직접 그리는 F9 성능 오버레이의 일부 텍스트
- GitHub에서 실시간으로 가져오는 영문 릴리스 노트
- 게임 본체 또는 다른 모드가 그리는 UI

기능의 내부 키(`fogPass`, `gcMode` 등)와 파일·설정 경로는 번역하지 않습니다. 검색 또는 오류 보고에 필요한 식별자이기 때문입니다.

## 설치 개요

> **주의: 현재 RC2를 기존 `be1f28a` + v4 환경에 직접 덮어쓰지 마세요.** 새 원본이 설치되지 않은 상태에서는 설치 스크립트가 해시 검사에서 중단하도록 설계되어 있습니다.

1. 기존 번역 패치를 해당 버전의 복원 스크립트와 백업으로 **원본 상태까지** 복구합니다. 복원 순서나 백업 파일이 불확실하면 중단하고 상태부터 확인하세요.
2. 원제작자의 `5c72380` **정식 설치 패키지**로 원본 PZ_Optimization을 업데이트합니다. GitHub 소스 ZIP은 게임에 바로 적용하는 설치 ZIP이 아닙니다. PZ_Optimization의 공식 업데이트 절차를 따르세요.
3. 게임 클라이언트를 완전히 종료합니다. 별도 데디케이트 서버는 건드리지 않습니다.
4. 새 원본이 설치돼 있고 이전 한국어 패치의 파일이 남아 있지 않은지 확인한 다음 `install-ko.ps1`을 실행합니다. 실행 시 해시가 맞지 않으면 아무것도 덮어쓰지 않습니다.
5. 메인 메뉴 **모드(Mods)**에서 `PZ Optimization Korean Translation` (`PZOptKorean`)을 활성화하고 게임을 완전히 재시작합니다.
6. **설정 → 최적화**의 상단·중간·하단, 설명 패널 및 ESC 메뉴를 확인합니다.

Windows PowerShell 예시(게임 폴더가 다르면 `-Game`을 지정):

```powershell
powershell -ExecutionPolicy Bypass -File .\install-ko.ps1 -Game 'D:\SteamLibrary\steamapps\common\ProjectZomboid'
```

백업은 기본적으로 사용자 바탕화면의 `PZOPT-Korean\backups`에 생성되며, 폴더가 없으면 자동으로 만듭니다. 백업 위치를 직접 지정하려면 `-BackupRoot`를 사용하세요(예: `-BackupRoot 'D:\PZOPT-Korean\backups'`). 성공 시 표시되는 `Backup:` 경로를 보관하세요. 설치 중에는 기존 게임의 Java 클래스, `projectzomboid.jar`, 저장 데이터, 사용자 `Zomboid/pzopt/options.ini` 및 서버 파일을 수정하지 않습니다. 단, 설치형 패치이므로 게임 설치 폴더의 **Lua 파일 네 개**는 교체합니다. 모드 활성화만으로 적용되는 순수 번역 모드와 구분해야 합니다.

### 제거와 원본 업데이트

게임 클라이언트를 종료한 뒤 설치 시 기록한 백업으로 복원합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\restore-ko.ps1 -BackupPath 'C:\Users\<사용자>\Desktop\PZOPT-Korean\backups\5c72380-KO-RC2-YYYYMMDD-HHMMSS-fff' -Game 'D:\SteamLibrary\steamapps\common\ProjectZomboid'
```

복원 스크립트는 현재 설치된 네 Lua 파일 및 번역 모드의 해시가 이 패치와 일치하는지 확인합니다. 사용자 임의 수정 또는 새로운 릴리스 파일이 감지되면 덮어쓰지 않습니다. 복원 후 번역 모드를 비활성화하거나 제거하고 원제작자의 공식 업데이트를 수행하세요. **한글 패치가 설치된 상태에서 원본의 자동 업데이트 버튼을 사용하지 마세요.**

## 이번 원본 업데이트에서 변경된 점

`4bb5acb`에서 `5c72380`으로 갱신되면서 원본의 **변경 파일 10개**를 대조했습니다. 번역 대상 UI Lua 및 `README.md`는 변경 목록에 없습니다. 기존 한·영 번역키 571개는 유지하며, 최적화 로직을 번역 패치에서 다시 구현하지 않습니다.

- **Windows 테두리 없는 창:** 원본 `Display.java`가 장식 없는 창의 생성 위치와 크기를 조정합니다. 메뉴 위치 및 실제 클릭 좌표가 어긋나던 문제(#14)를 수정하려는 변경입니다. 사용자 환경에서의 해결 여부는 별도 테스트가 필요합니다.
- **ESC 일시정지 메뉴 FPS:** 원본 `FrameCap.java`가 일시정지 메뉴도 별도로 설정한 메뉴 프레임 제한의 대상으로 포함합니다. 한국어 패치는 이 Java 코드를 교체하지 않습니다.
- 변경된 개발 하네스·문서·Workshop 문구는 게임 내 번역 항목이 아니므로 번역 키 추가는 없습니다.

이 RC2는 **공식 설치 ZIP의 빌드 정보가 `commit=5c72380`인지, 네 UI Lua 파일 해시가 예상한 원본과 일치하는지 검사한 뒤에만 설치**됩니다. 로컬에서 공식 릴리스의 422개 파일 설치·검증과 RC2 적용을 완료했고, 한국어 설정 화면 표시 및 관찰한 ESC 메뉴 테스트에서 오류 미발생을 확인했습니다. 장시간·멀티플레이 검증은 남아 있습니다.

## 알려진 제한 사항

- 원본은 정확한 게임 JAR revision에 묶입니다. 다른 빌드에서는 원본 클래스 오버라이드가 활성화되지 않을 수 있습니다.
- 원제작자의 README는 싱글플레이 벤치마크를 주로 다룹니다. 멀티플레이는 상대적으로 검증 범위가 작으며 데디케이트 서버에는 원본 클래스 파일을 설치하지 않는다고 안내합니다.
- 기존 `be1f28a`에서 특정 환경의 안개 깜빡임은 `fogPass=false`로 회피한 사례가 있습니다. 모든 사용자에게 필요한 설정은 아닙니다.
- `be1f28a`에서 발생한 ESC 메뉴 `centerKeybindings` 오류의 초기화 경로는 이후 원본 릴리스에서 수정되었습니다. 본 RC2는 그 수정 코드를 보존하도록 소스를 병합했습니다. 사용자 환경의 현재 테스트에서는 ESC 오류가 재현되지 않았으나, 간헐 오류의 완전한 해결 여부는 장시간 검증이 필요합니다.
- **성능 측정 기능**인 프레임별 로그와 샘플링은 일반 플레이에서 추가 부하를 만들 수 있습니다. 필요한 경우에만 사용하세요.

## 번역 및 릴리스 관리

- 원본 릴리스와 개발 브랜치를 구분합니다. 이번 패치는 `5c72380` 배포 릴리스의 변경 파일 10개와 이전 전체 선별 소스의 합집합을 기준으로 준비했습니다. 최신 `master`와의 일치는 별도로 확인해야 합니다.
- 새 릴리스가 나오면 우선 원본 전체 파일 목록을 비교합니다. Java·Lua 기능 변경과 단순 문서 변경을 분리하고 번역 키 추가·변경·삭제를 검토합니다.
- 원본 코드에서 변경된 부분은 최신 원본을 우선합니다. 번역을 위해 필요한 `getText()` 호출만 다시 적용하고, 내부 설정값이나 실제 최적화 동작은 변경하지 않습니다.
- 정적 검사만으로 게임 표시와 호환성을 보장하지 않습니다. 로컬 게임 테스트 후 검증된 패치만 정식 릴리스로 승격합니다.
